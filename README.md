# Smoking Zen

Smoking Zen — приватный русскоязычный штаб команды кальянного бара в Telegram. В одном Mini App собраны задачи, оперативные знания, контакты, документы и безопасные ссылки на записи в Bitwarden. Данные разделены по рабочим пространствам; браузер не получает сервисные ключи Supabase, Telegram-токен или прямой доступ к приватным файлам.

## Как открыть приложение

Рабочий вход выполняется из личного чата с доверенным Telegram-ботом: через Menu Button, прямую ссылку Mini App либо подписанную ссылку на приглашение или задачу. Сервер проверяет подпись и возраст `initData`, а затем создаёт HTTP-only сессию. Скопированная обычная браузерная ссылка без Telegram-контекста не заменяет такой вход: приложение покажет безопасный экран с предложением открыть бота. Активный владелец создаёт 24-часовую ссылку в разделе «Люди → Команда», копирует или отправляет её; роль всегда остаётся `member`, а приглашение погашается один раз.

## Локальный запуск

Требуются Node.js 24.18.0 и pnpm 10.14.0. Установите зависимости командой `pnpm install --frozen-lockfile`, скопируйте `.env.example` в локальный файл окружения и используйте только тестовые значения. Для интерфейсной разработки разрешён явный `APP_MODE=demo`; staging и production работают с `APP_MODE=production`. Секреты разбираются лениво: сборка их не требует, а защищённая операция при неполной конфигурации fail-closed завершается до эффектов.

Основные проверки:

- `pnpm lint` и `pnpm typecheck`;
- `pnpm test` для Vitest и миграций PGlite;
- `pnpm test:scripts` и `pnpm lint:shell` для резервного копирования и восстановления;
- `pnpm test:e2e` для светлого/тёмного desktop, Telegram Web, Android portrait/landscape и двух размеров iOS WebKit;
- `pnpm test:e2e:production` после сборки для production-заголовков и браузерного экрана «Открыть в Telegram» на `next start`;
- `APP_MODE=production pnpm build` для production-сборки без runtime-секретов;
- `pnpm audit --prod --audit-level high` для production-зависимостей.

Схема базы находится в `supabase/migrations`, проектные задания Cron — в `supabase/operations`, инструкции эксплуатации — в `docs`. Реальные ключи, токены и пароли хранятся только в защищённых переменных платформ, Supabase Vault или менеджере секретов; в репозиторий они не попадают.
